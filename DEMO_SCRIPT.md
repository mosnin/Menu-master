# Deal Desk — Founder Demo Script

**Total runtime:** ~17 minutes  
**Prerequisites:** App running locally (`pnpm dev`), seed data loaded, Auth0 configured.

---

## Setup (2 min)

1. Start the app: `pnpm dev` (runs on `http://localhost:3000`)
2. Start Inngest dev server in a second terminal: `pnpm inngest:dev`
3. Open the browser to `http://localhost:3000`
4. Sign in as **Maria Gonzalez** (broker_admin) — this gives the fullest view of the platform
5. Confirm you land on the dashboard at `/dashboard`

> **Talking point:** Maria is a broker admin at Realty Partners Group. She manages agents and coordinators and has full visibility across all transactions.

---

## Act 1: Dashboard (3 min)

**URL:** `/dashboard`

- **Portfolio overview:** Point out the transaction summary cards — active, draft, pending closing, closed.
- **Health cards:** Highlight the health indicators for each active transaction. The 742 Evergreen transaction shows issues (overdue checklist item, failed extraction). The 900 Baseline Rd transaction shows it is near closing.
- **Digest link:** Click through to `/digest` to show the daily digest view. Explain that this is auto-generated by Inngest background jobs and can be emailed via Resend.

> **Talking point:** This is the broker's morning view. In one screen, Maria knows which deals need attention and which are on track.

---

## Act 2: Active Transaction — 742 Evergreen Terrace (5 min)

### Overview

**URL:** `/transactions/[id]/overview` (click the 742 Evergreen card from the dashboard)

- Show the transaction summary: status (active), parties, key dates, property details.
- Point out the transaction health indicator.

### Documents

**URL:** `/transactions/[id]/documents`

- Show the documents list. Highlight:
  - A document with **successful AI extraction** — click into it to show extracted fields (contract price, dates, parties). Explain that OpenAI processes uploads automatically.
  - A document with **failed extraction** — show the error state and explain that manual review is the fallback path.
- Mention the document request flow at `/transactions/[id]/documents/requests`.

### Checklist

**URL:** `/transactions/[id]/checklist`

- Show the auto-generated checklist items.
- Highlight the **overdue item** — point out the visual indicator and how it surfaces in the dashboard health cards.
- Show how items can be marked complete.

### Approvals

**URL:** `/transactions/[id]/approvals`

- Show the **pending approval** on this transaction.
- Explain the approval gating model: certain actions or status transitions require broker approval before proceeding.
- Walk through the approve/reject flow.

> **Talking point:** This is a real transaction with real friction — overdue items, failed extractions, pending approvals. The platform surfaces problems instead of hiding them.

---

## Act 3: Closing Room — 900 Baseline Rd (3 min)

**URL:** `/transactions/[id]/closing` (navigate to the 900 Baseline Rd transaction)

- **Closing readiness score:** Show the overall readiness indicator. Explain what feeds into it.
- **Lender milestones:** Show lender progress tracking — appraisal, underwriting, clear to close.
- **Title progress:** Show title/escrow status tracking.
- **Document requests:** Show outstanding document requests and their status.
- **Collaborators:** Navigate to `/transactions/[id]/collaborators` to show external parties (lenders, title companies) with token-based access.

> **Talking point:** Closings fail because of coordination gaps. This view gives everyone — agent, coordinator, broker — a single source of truth on closing readiness.

---

## Act 4: Broker View (3 min)

### Broker Overview

**URL:** `/broker`

- Show the brokerage-level portfolio view. All transactions across agents are visible here.
- Point out aggregate health and pipeline status.

### Forecast

**URL:** `/broker/forecast`

- Show the revenue forecast based on pending and near-closing transactions.
- Explain how economics data (commission splits, GCI) feeds this view.

### Compliance

**URL:** `/broker/compliance`

- Show compliance status across the portfolio.
- Highlight any flagged transactions or missing documentation.

> **Talking point:** Broker admins don't need to open every deal to know the state of their business. This is the 30,000-foot view with drill-down capability.

---

## Act 5: Operational Features (2 min)

### Work Queue

**URL:** `/queue`

- Show the prioritized work queue. Items are surfaced based on urgency, role, and due dates.
- Explain how different roles see different queue items.

### Analytics

**URL:** `/analytics`

- Show the analytics dashboard with pipeline and performance metrics.

### Getting Started

**URL:** `/getting-started`

- Show the onboarding guide for new users. Useful for pilot rollout.

> **Talking point:** The platform doesn't just store data — it tells each user what to do next. The queue is the daily driver for coordinators and agents.

---

## Wrap-up (1 min)

Summarize the four pillars:

1. **AI extraction** — Documents are processed automatically. Manual review is the fallback, not the default.
2. **Approval gating** — Status transitions and critical actions require explicit broker sign-off.
3. **Closing readiness** — A single view tracks every dependency for getting to the closing table.
4. **Economics views** — Broker admins see forecast, compliance, and portfolio health without opening individual deals.

> **Final point:** This is a transaction management platform built for how real estate actually works — hierarchical roles, document-heavy workflows, and multi-party coordination under deadline pressure.
